# TLS Modes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `prefer` and `require` TLS modes so encrypting a connection no longer requires either a pinned CA path or a downgrade to cleartext, and realign URL `sslmode` parsing with libpq.

**Architecture:** `ConnectionConfig.TLSMode` grows from two cases to four. `PostgresConnector.makeTLS` maps them onto PostgresNIO's existing `.disable` / `.prefer` / `.require` TLS cases, so the `prefer` fallback needs no retry logic of our own. The app replaces its boolean TLS toggle with a four row picker, and a new `TLSFailureClassifier` lets the error banner offer a one click step down from `verifyFull` to `require` when, and only when, a certificate verification failure is positively identified.

**Tech Stack:** Swift 6, SwiftUI, PostgresNIO, NIOSSL, swift-testing.

**Spec:** `docs/superpowers/specs/2026-07-28-tls-mode-design.md`

## Global Constraints

- Test framework is swift-testing (`import Testing`, `@Suite`, `@Test`, `#expect`, `#require`). Not XCTest.
- Indentation: `Sources/LithePGCore` and `Tests/LithePGCoreTests` use 4 spaces. `Sources/LithePGApp` and `Tests/LithePGAppTests` use 2 spaces. Match the file you are editing.
- User facing copy uses no em-dashes, no Oxford commas, and restrained apostrophes. This applies to every picker label, caption, warning, and error string in this plan.
- The default TLS mode for remote hosts stays `verifyFull`. Every weaker mode must be an explicit user choice. Never downgrade automatically.
- Build with `swift build`. Run a focused suite with `swift test --filter <SuiteName>`.
- Commit after every task with a signed commit (`git commit -s`).

```swift
    // Internal rather than private so the mode mapping is directly testable.
    func makeTLS(for config: ConnectionConfig) throws -> PostgresConnection.Configuration.TLS {
        switch config.tlsMode {
        case .disable:
            return .disable
        case .prefer:
            return .prefer(try makeSSLContext(verifying: false, pinnedRootCertificatePath: nil))
        case .require:
            return .require(try makeSSLContext(verifying: false, pinnedRootCertificatePath: nil))
        case .verifyFull:
            return .require(
                try makeSSLContext(
                    verifying: true,
                    pinnedRootCertificatePath: config.pinnedRootCertificatePath
                )
            )
        }
    }

    private func makeSSLContext(
        verifying: Bool,
        pinnedRootCertificatePath: String?
    ) throws -> NIOSSLContext {
        var tls = TLSConfiguration.makeClientConfiguration()
        if verifying {
            if let path = pinnedRootCertificatePath {
                // Preflight: surface a clear error early rather than an opaque NIOSSL IOError later.
                guard !path.isEmpty, FileManager.default.isReadableFile(atPath: path) else {
                    throw PostgresConnectorError.pinnedRootCertificateUnreadable(path: path)
                }
                // REPLACE the default trust roots, not add. On Darwin, the default path
                // runs through SecTrust, which rejects self-signed/internal-CA server certs
                // even when added as an additional anchor. A file-based trustRoots takes
                // the BoringSSL verification path and accepts the pinned CA.
                tls.trustRoots = .file(path)
            }
        } else {
            // prefer and require encrypt without authenticating the server. This is weaker than
            // verifyFull and is only ever reached by an explicit user choice.
            tls.certificateVerification = .none
        }
        return try NIOSSLContext(configuration: tls)
    }
```

```swift
import Foundation
import NIOSSL

/// Decides whether a connection failure was caused by server certificate verification, and so
/// whether stepping down from `.verifyFull` to `.require` could plausibly succeed.
///
/// Deliberately conservative. Anything not positively identified as a certificate problem
/// returns `false`. A false negative costs the user a manual mode change. A false positive
/// offers a security downgrade in response to an unrelated failure, which is worse.
public enum TLSFailureClassifier {
    public static func isCertificateVerificationFailure(_ error: any Error) -> Bool {
        if let extra = error as? NIOSSLExtraError {
            switch extra {
            case .failedToValidateHostname, .serverHostnameImpossibleToMatch:
                return true
            default:
                return false
            }
        }

        if let sslError = error as? NIOSSLError {
            switch sslError {
            case .unableToValidateCertificate, .noCertificateToValidate:
                return true
            case .handshakeFailed(let boringSSLError):
                return describesCertificateVerification(boringSSLError)
            default:
                return false
            }
        }

        return false
    }

    /// BoringSSL reports verification failures through an error stack rather than a typed case,
    /// so the reason text is the only available signal. Match the specific verification strings
    /// rather than treating every handshake failure as a certificate problem.
    private static func describesCertificateVerification(_ error: BoringSSLError) -> Bool {
        let description = String(describing: error).lowercased()
        let markers = [
            "certificate_verify_failed",
            "certificate verify failed",
            "unable_to_get_issuer",
            "self_signed_certificate",
            "self signed certificate",
            "unable_to_verify_leaf_signature",
            "certificate_has_expired",
            "hostname mismatch",
        ]
        return markers.contains { description.contains($0) }
    }
}
```

  /// Re-runs the last connection attempt with certificate verification off. Only ever reached

  public func retryWithEncryptionOnly() async {
